# 技术架构与实施计划

目标：Windows 10/11 x64，本地单用户，原生 Qt 窗口，无本地 Web 服务。开发语言 Python 3.12，发行版内置运行时，不检测用户 Python。SQLite WAL 保存业务数据；Windows DPAPI CurrentUser 保存密钥，仅同一 Windows 用户可解密。UI 不接触密钥明文。

数据流：XLSX 流式读取 → 用户字段映射 → 事务批量入库 → 文章版本 → 冻结配置与案例的任务 → 有界 worker → 全文分块 → 结构化 JSON 校验 → 原文逐字证据定位 → 下架门槛 → 复核 → 待审核案例 → 审核后检索。任务成功落库与状态提交在同一事务，恢复不派发已成功项。

阶段：M0 样本核验（缺附件，待验收）；M1 数据管理与原生窗口；M2 API/证据；M3 调度与恢复；M4 案例/复核；M5 20 万持久化与调度模拟；M6 Windows 打包和目标机验收。每个阶段测试通过后继续开发；真实样本和 Windows 阶段门槛不因 Linux/模拟测试而视为通过。

边界：AI 只给建议；不实现知识库上下架接口；不默认联网检索事实；用户明确授权并选择模型后才可发送正文。真实接口质量必须用真实模型与人工金标准集另验，500 篇标注集缺失时不声称 precision/recall 达标。原文和公司 Excel 不提交 Git。

验收策略：自动化测试导入/去重/版本、证据与 schema、HTTP 错误、暂停/恢复/幂等/取消/预算、案例隔离、复核导出、备份；模拟 200,000 条数据与任务；Qt 无头交互；Windows CI 产生 EXE，再在干净 Windows 验证 DPAPI/启动/恢复。构建成功不等于 Windows 验收完成。
